## Промт: раздел «Цели» (Goals)

**Общая идея:** долгосрочный контейнер над привычками. Цель = что человек хочет достичь; внутри неё — ежедневные задания/действия и дневник рефлексии. Два вида: День и Месяц.

### Сущности

**Goal**
- название, тип (количественная / процессная), дата старта, дедлайн (опционально)
- статус: активна / завершена / архив
- шаблон ежедневных заданий (авто-ротация или заданный пользователем список)
- лимит активных целей на бесплатном тарифе (по аналогии с лимитом 5 привычек) → апсейл в Pro

**Task**
- текст задания, привязка к goal_id и к конкретной дате
- источник: авто из шаблона / добавлено вручную на день
- статус: не начато / выполнено / пропущено / частично (если заданий на день несколько)

**DailyEntry**
- дата, goal_id
- текст дневниковой записи, автосохранение без кнопки «сохранить»
- опционально: оценка настроения (смайлик), фото-подтверждение

### Навигация и переключение целей

- Горизонтальный ряд чипов вверху (скролл, если целей много), один активный чип = текущий фокус экрана
- «+» в конце ряда — модалка создания цели: название → тип → дедлайн (опц.) → выбор шаблона заданий или ручной ввод
- Долгий тап по чипу → меню: редактировать / архивировать / удалить
- При достижении лимита целей на free-тарифе — попытка создать новую показывает Pro-плашку вместо модалки создания

### Экран «День»

- Заголовок: дата + день недели, свайп влево/вправо или стрелки для навигации по любым дням (не только сегодня)
- Блок задания: чекбокс(ы) — если заданий несколько, список; тап по чекбоксу = мгновенное выполнение без подтверждения
- Тап по тексту задания (не по чекбоксу) — разворачивает детали задания, если есть
- Поле дневника: автосохранение по мере ввода; плейсхолдер адаптивный — один текст если задание выполнено, другой (рефлексия «что помешало») если пропущено
- Для будущих дат: задание видно (если уже сгенерировано по шаблону), дневник недоступен для ввода
- Для прошедших дат: и чекбокс, и дневник редактируемы задним числом
- Нижняя панель:
  - иконка стрика/буста — открывает текущую серию дней подряд с выполненным заданием, с историей рекордов
  - «+» — добавление разового произвольного действия/заметки, не привязанного к шаблону
  - смайлик — отдельная оценка настроения/самочувствия за день, не связана напрямую с фактом выполнения задания

### Экран «Месяц»

- Календарная сетка, статусы дня:
  - выполнено (чекбокс закрыт)
  - день прошёл, но задание не выполнено
  - частично выполнено (если заданий несколько и закрыты не все — визуально отличается от «полностью выполнено»)
  - сегодняшний день — отдельная рамка/маркер поверх любого из статусов
  - будущие дни — нейтральные, без статуса
- Тап по числу → переход на экран «День» этой даты
- Свайп между месяцами, индикатор страниц под сеткой
- Блок «Ваши записи» ниже календаря: лента дневниковых записей за текущую цель, обратный хронологический порядок, карточка = дата + превью текста (2-3 строки), тап → открывает день целиком

### Дополнительная логика

- Завершение цели по дедлайну → экран итогов (% выполненных дней, лучший стрик, количество записей в дневнике) — по аналогии с Winter Arc Recap
- Пустое состояние без целей → онбординг создания первой цели
- Связь с существующим habit-трекером: задание дня внутри цели технически может быть той же сущностью, что и привычка — не дублировать модели данных, а переиспользовать

1. Критические баги (must-fix, блокируют релиз)
1.1. Таймер «Отказы» — цифры наезжают друг на друга во время тика
Экран: Tracker → вкладка «Отказы», десктоп. Что происходит: каждую секунду, когда меняется значение таймера (дни · чч:мм:сс), цифры временно отрисовываются в аномально большом кегле и наезжают на соседнюю карточку и друг на друга — «12» и «02:51:33» накладываются внахлёст, «Соцсети до сна» становится нечитаемым. Через 1–2 тика вёрстка «отпускает» и всё встаёт на место — то есть это не единичный визуальный сбой, а системная проблема анимации/перерасчёта ширины моноширинного блока при каждом обновлении таймера. Почему критично: это самый частый элемент экрана — таймер тикает постоянно, пока пользователь смотрит на карточку. Мигающий разъезжающийся текст на key retention-фиче (счётчик отказа от вредной привычки) выглядит как сломанное приложение, а не premium-продукт. Требуемое исправление:

Зафиксировать font-variant-numeric: tabular-nums и фиксированную ширину-контейнер под формат ДД · ЧЧ:ММ:СС, чтобы перерисовка не меняла box-модель.
Убрать любой transition/scale на смену текста таймера — обновление должно быть мгновенным, без «прыжка» кегля.
Добавить overflow: hidden + white-space: nowrap на карточку отказа, чтобы при любом сбое текст обрезался, а не наезжал на соседние карточки.
Прогнать вживую 60 секунд подряд на все 3 карточки одновременно (сигареты/сахар/соцсети) — баг должен исчезнуть на всех, не выборочно.
1.2. Перенос текста ломает карточки при живых данных
Экран: Tracker → «Отказы» (тот же composer-стейт), а также хедер («WINTER ARC · ДЕНЬ 14» → переносится в «ДЕНЬ / 14»). Что происходит: дата «с 7 сентября» переносится посередине на «с 7» / «сентября» — карточка «Сахар» становится на строку выше двух соседних, всё съезжает. Заголовок раздела «WINTER ARC · ДЕНЬ 14» в одном из состояний переносится на «ДЕНЬ» / «14» в две строки, портя вертикальный ритм хедера. Почему критично: макет был протестирован только на «удобных» коротких значениях («с 30 августа»). Реальные данные (дата регистрации привычки, разные месяцы) будут ломать вёрстку у всех пользователей рано или поздно — это не крайний случай, это гарантированный сценарий. Требуемое исправление:

Для подписи даты — white-space: nowrap, при нехватке места сокращать формат («с 7 сен») вместо переноса.
Для заголовка хедера — уменьшать кегль на маленьких контейнерах адаптивно, либо сокращать «ДЕНЬ 14» → «Д.14» до того, как дойдёт до переноса.
Протестировать на предельных значениях: «с 1 января», «с 30 декабря», «День 100 из 90» (просрочка), трёхзначные счётчики (999 дней), двойные почётные метки (замок + бейдж) — всё это должно не ломать сетку.
1.3. Нет экрана/модуля настроек — при этом от него явно ждут многого
Иконка шестерёнки присутствует в хедере мобильной версии Today, но:

ни один из 5 экспортированных файлов не содержит самого экрана настроек;
при этом в задаче есть отдельное требование «смена языка это тоже по-хорошему максимально качественно» — то есть ожидание полноценного, глубоко проработанного модуля, а сейчас нет даже заглушки.
Это самая большая дыра во всём макете: без экрана настроек невозможно оценить и невозможно закрыть половину пунктов из этого аудита (язык, тема, уведомления, приватность, аккаунт, единицы измерения, управление подпиской Pro). Подробное ТЗ на этот экран — в разделе 5.

2. Экран за экраном
2.1. Today / «Сегодня» — mobile
Что сделано хорошо:

Хедер «WINTER ARC · День 14 из 90» с иконкой настроек и аватаром — чисто, дышит, иерархия читается с первого взгляда.
Блок «Эта неделя» (7 кружков по дням) — активный/текущий день выделен обводкой, а не заливкой — аккуратное отличие «сделано» vs «сегодня, ещё не сделано».
Карточка «Аналитика дня» (кольцо-прогресс 67%, разбивка Тело/Разум/Дисц.) и Pro-апсейл рядом — контраст ледяной/золотой палитры работает именно так, как описано в инструкции — золото читается как единственный premium-акцент, а не декор.
Список привычек «Сегодня» — чекбокс + иконка категории + название + недельная история точками + счётчик стрика в одной строке — плотно, но не перегружено.
Pomodoro-таймер с табами Фокус/Короткий/Длинный, крупным кольцом-циферблатом и тремя круглыми кнопками управления — визуально сильный, самый «дорогой» блок экрана.
Что критично не работает / вызывает вопросы:

Нет визуального разделения «выполнено» и «доступно, но не сделано» на уровне строки списка — только чекбокс. При 6+ привычках в списке (а Pro-лимит явно выше 4) взгляд не «сканирует» список быстро, потому что чек — единственный сигнал.
Блок «Настроение» (5 эмодзи-лиц) не имеет подписи, что происходит с выбором дальше — сохраняется ли он в аналитику дня, влияет ли на что-то видимое пользователю сейчас же. Механика введена, но не «продана» пользователю визуально — непонятно, зачем её нажимать.
Планер внизу («18:00 Встреча с командой», «Днём Растяжка вечером») смешивает временные и не-временные пункты без визуальной логики сортировки — конкретное время и абстрактное «днём» в одной колонке рядом выглядят как баг вёрстки, а не как продуманный дизайн (хотя вероятно это осознанное решение — тогда это решение не считывается пользователем).
Иконка настроек по размеру визуально теряется рядом с аватаром — кликабельная зона маленькая для мобильного тач-таргета (должно быть ≥44×44px по факту нажимаемой области, не только иконки).
2.2. Today — desktop
Сетка bento-стиля в целом повторяет референс, карточки разного веса (Планер/Сегодня — списки, Настроение/Стрик — компакт, Pomodoro — крупный) — это заявленное «не все карточки одинаковые» реализовано корректно.
Расхождение с референсом: в нижнем ряду вместо заявленной в референсе карточки «Лучший стрик» (21 день, рекорд арки) в факте отрендерена карточка «Личный рекорд» (Жим лёжа 80кг×5). Это может быть осознанное расширение функционала (спортивные PR), но тогда пропадает изначальная карточка «Лучший стрик», которая была важной мотивационной метрикой — нужно решить: обе карточки нужны, и тогда добавить 4-ю колонку, либо это осознанная замена — тогда зафиксировать её в дизайн-инструкции, чтобы Today и Profile не спорили друг с другом по составу метрик.
Правая рельса-навигация: активный пункт подсвечен заливкой — ок, но при 5 иконках без подписей единственная подсказка — цвет/фон; нет tooltip при наведении (на десктопе это ожидаемый паттерн, его отсутствие — не критично, но дешёвое упущение).
2.3. Tracker / «Трекер» — вкладка «Привычки»
Экспортированный файл содержит вкладку, но ни один скриншот фактического рендера вкладки «Привычки» предоставлен не был (все снимки — по вкладке «Отказы»). Это слепая зона аудита: нельзя подтвердить, что список привычек, фильтры и состояния (пустой список, все выполнены, просрочка) реализованы и не содержат тех же классов багов, что и «Отказы» (перенос текста, наложение чисел, устойчивость к длинным названиям). Требование к следующей итерации — прислать скриншот этой вкладки отдельно.

2.4. Tracker — вкладка «Отказы»
Идея сильная и отличается от типового habit-трекера: не «сделай», а «продержись» — таймер с последнего срыва, ближайшая цель (3д/7д/14д/30д/90д), прогресс-бар и точки-чекпоинты. Это единственный по-настоящему уникальный механик из всех пяти экранов.
Баги 1.1 и 1.2 (см. раздел 1) относятся именно сюда и должны быть закрыты в первую очередь — именно на этом экране макет физически ломается на глазах.
Композер добавления нового отказа (От чего отказываешься + кнопка «Добавить») всплывает без видимой точки входа на скриншоте — неясно, где именно пользователь нажимает «+», чтобы вызвать это поле; кнопка закрытия (×) есть, кнопка открытия — не видна ни на одном кадре. Нужно явно показать: плавающая кнопка, пункт в шапке раздела или что-то ещё — сейчас это выглядит как случайно открывшееся состояние.
Чекпоинты цели (3д/7д/14д/30д/90д) у всех трёх карточек показывают одинаковый набор точек независимо от типа отказа — вероятно правильно, но не проверено: должна ли «ближайшая цель» быть настраиваемой пользователем (кто-то бросает курить, кто-то ограничивает соцсети — разумные горизонты целей у них разные) — сейчас это жёстко зашито визуально, стоит явно решить, редактируется ли это в самой карточке или только при создании.
2.5. Calendar / «Планер»
По исходному файлу (скриншотов рендера не предоставлено — аудит по разметке): экран содержит вкладки Неделя/День/Месяц на десктопе, мини-календарь и разбивку времени в сайдбаре, на мобильном — сворачиваемый месяц, выбор дня, таймлайн и распределение времени. Структурно это самый сложный из пяти экранов (больше состояний, больше видов). Риски, требующие обязательной проверки визуальным рендером в следующей итерации:

Таймлайн с почасовой шкалой (упомянут в предыдущих итерациях проекта как отдельное требование) — по коду не видно, реализован ли реальный drag/scroll по часам или это статичный список без учёта фактического времени.
Popover создания задачи (НОВАЯ ЗАДАЧА, НАЧАЛО/КОНЕЦ/ЗАМЕТКА) — на узких карточках именно такие поля (время начала-конца) чаще всего страдают от переноса текста, как в баге 1.2 — нужно явно перепроверить на мобильной ширине.
Нет подтверждения, что вид «Месяц» на мобильном не превращается в нечитаемую сетку 5×7 с текстом внутри ячеек 40px — на телефоне это самое частое место провала в календарных интерфейсах.
2.6. Training / «Тренировки»
По исходному файлу: разделы «Цели», «Задания», «Ваши записи», счётчик «Число записей», состояние «Цель завершена». Отдельно в архиве проекта обнаружен скриншот screenshots/overview.png с экраном «Зал» (хлебная крошка «‹ Все разделы», карточки CONSISTENCY, MONTHLY GOAL — подписи на английском, тогда как весь остальной продукт полностью на русском). Важно: эта именно комбинация текста не найдена ни в одном из пяти актуальных .dc.html файлов — похоже, это скриншот более старой версии экрана, оставшийся в архиве проекта. Но раз он там лежит и раньше существовал английский вариант подписей — это сигнал риска рецидива: при следующей правке Claude Design может «вспомнить» старый паттерн карточки и снова вставить CONSISTENCY/MONTHLY GOAL вместо русского. Явно фиксируем в промте ниже: 100% текста в интерфейсе — только на языке, выбранном пользователем (RU по умолчанию), без исключений для отдельных карточек. Также в архиве обнаружен скриншот с явным рендер-багом — большая пустая белая область поверх карточек статистики (очки «742», ring-прогресс, дневные метрики) — похоже на незагруженный/сломанный слой (возможно скроллбар или недорисованный элемент). Нужно воспроизвести и закрыть перед сдачей.

2.7. Profile / «Профиль»
По исходному файлу: hero-блок, bento-сетка метрик, «История индекса», «Корреляции», карусель «Рекомендации», Pro-баннер, сравнение Arc 1/Arc 2, «Индекс дисциплины». Функционально это самый «тяжёлый» по данным экран (история, корреляции, сравнение периодов) — и одновременно единственный, где нет вообще ни одного скриншота фактического рендера. Учитывая, что именно на этом экране больше всего динамических чисел, графиков и подписей произвольной длины (имена привычек, названия корреляций) — по статистике именно здесь наиболее вероятны те же классы багов, что в 1.1 и 1.2, просто ещё не пойманные на скриншотах. Приоритет для следующей проверки.

3. Мультиязычность и смена языка — детальное ТЗ
Сейчас в проекте нет ни экрана настроек, ни зафиксированного описания, как должна работать смена языка — есть только словесная фраза «смена языка тоже должна быть максимально качественной» и один тревожный прецедент нарушения (англ. подписи на «Зал»). Ниже — минимальный набор требований, без которых «смена языка» не будет ощущаться качественной:

Полный охват — переключатель должен покрывать 100% строк интерфейса: заголовки, лейблы полей, плейсхолдеры, тексты кнопок, системные статусы («выполнено», «просрочено»), форматы даты/времени, единицы измерения (кг/lb, км/mi — если это фитнес-метрики), названия дней недели и месяцев, форматы множественного числа («1 день / 2 дня / 5 дней» — в русском 3 формы, в английском 2, это разные правила и их нельзя закрыть одной строкой).
Переключатель — часть экрана настроек, а не скрытая или случайная функция; должен быть заметен, но не навязчив (обычно — список с текущим значением, ведущий на отдельный экран выбора).
Без перезагрузки/потери контекста — смена языка должна применяться мгновенно, пользователь не должен терять место в приложении (если он был на экране Tracker → Отказы, после смены языка он должен остаться там же).
Числа и даты форматируются по языку, а не только переводятся статичные подписи — 25 сентября / September 25 — разный порядок день/месяц.
Явный запрет смешения языков внутри одного экрана — зафиксировать отдельным пунктом в промте ниже, так как прецедент уже был (карточки «Зал»).

5. Экран настроек — обязателен к добавлению (спецификация для промта)
Отдельного экрана нет ни в одном файле. Ниже — минимальный состав, который нужно заказать:

Профиль/аккаунт — имя, аватар, e-mail/способ входа.
Язык — RU/EN (см. раздел 3), с чёткой индикацией текущего значения.
Тема — упомянутая в прошлых итерациях Night/Daylight — либо реализовать выбор, либо явно зафиксировать, что продукт only-dark, и убрать переключатель темы из бэклога, чтобы не жить с недоделанным пунктом.
Уведомления — по привычкам, по Pomodoro-сессиям, по завершению Arc.
Единицы измерения — если есть спортивные метрики (жим лёжа 80кг — видели на Today) — кг/фунты.
Управление подпиской Winter Arc Pro — статус, дата продления, отмена.
Данные арки — старт нового Arc, архив прошлых Arc (упомянуто в Профиле «Arc 1 / Arc 2»).
Приватность/данные — экспорт, удаление аккаунта — базовая гигиена, обычно ожидается даже от MVP.

1. Критические баги — с точным решением
1.1. Таймер «Отказы» наезжает цифрами при каждом тике
Проблема: каждую секунду цифры ДД·ЧЧ:ММ:СС временно увеличиваются и наезжают на соседнюю карточку.

Решение (точная спецификация):

Формат таймера — фиксированный шаблон Д · ЧЧ:ММ:СС, где под блок целиком резервируется контейнер шириной 14ch при font-variant-numeric: tabular-nums; font-feature-settings: "tnum".
Дни — отдельный &lt;span&gt; с min-width: 3ch; text-align: right (резерв под 3-значные числа сразу, а не «пока не понадобится»).
Часы/минуты/секунды — три &lt;span&gt; по 2ch каждый, разделители : — свой &lt;span&gt; с width: 1ch, не часть текстовой строки.
На обновление текста: transition: none явно (никакого scale/opacity на смену контента таймера — только сам текст меняется, контейнер — никогда).
Карточка отказа целиком: overflow: hidden; white-space: nowrap — это страховка на случай, если где-то ещё останется расчёт ширины.
Приёмка: 90 секунд живого тика одновременно на всех карточках, без единого кадра наложения — это единственный критерий «готово».
