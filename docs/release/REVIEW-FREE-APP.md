# Результат исправлений: бесплатный VeyrArc

Изменения подготовлены от `veyrarc-app` (`71ae04d`) в отдельной ветке `fix/free-app-reliability`. Приложение сохранено на существующих React, TypeScript, Vite и Supabase; переписывания с нуля нет.

| Область | Что сделано |
|---|---|
| Бесплатное приложение | Удалены платёжные экраны, тарифы, обращения к subscriptions, реферальный frontend и функция billing. Убраны ограничения привычек/целей и закрытые блоки аналитики. Старые ссылки перенаправляются на главную. |
| Восстановление пароля | Удалены кнопка, экран и вызовы сброса. Старый `/reset` ведёт на вход. Смена пароля авторизованным пользователем сохранена. |
| Офлайн и смена аккаунта | Очередь хранится отдельно для каждого владельца, включает создание/редактирование/удаление и дневник. Записи отправляются последовательно, переключение аккаунта отменяет активную отправку и устаревшие callbacks. Ошибочные операции сохраняются отдельно. |
| Кэш и история | Ключи системного состояния, календаря и статистики привязаны к аккаунту. История и экспорт загружаются страницами; ошибка страницы не выдаётся за полную статистику. |
| Импорт | Проверка формата и ссылок, стабильные новые ID, один серверный вызов/транзакция. Неудачный импорт откатывается, повторный запрос не дублируется. Существующие записи за совпадающий день сохраняются. |
| Авторизация | Профиль загружается с проверкой ошибок и владельца. Вместо зависшего экрана доступна повторная попытка. Ошибка выхода показывается пользователю. |
| SQL | Подготовлена миграция отключения коммерческих функций, единых заморозок, атомарных записей с RLS и безопасного search_path. Новые пользователи больше не получают техническую запись подписки. Действующие пользовательские данные не удаляются. |
| Среды | Сборка проверяет адрес/тип среды, запрещает известную рабочую базу в staging и смешение demo с backend-ключами. Старый скрипт, который без аргументов менял Supabase/Render и запускал деплой, отключён. |
| Зависимости и CI | Vite обновлён до 8.3.5, React Router до 7.18.5, обновлены уязвимые транзитивные зависимости. Включён strict TypeScript. Добавлен GitHub Actions workflow с тестами и сборкой без деплоя. |

## Что проверено локально

- `VITE_DEMO=1 npm run check`: TypeScript, 23 автоматических теста, 59 проверок разбора голосовых команд и production-сборка — успешно.
- SQL проверялся в реальном PostgreSQL через PGlite: RLS, чужие записи, rollback, повторный запрос, ограничения RPC, новая и частично развёрнутая схема без коммерческих таблиц.
- `VITE_DEMO=1 npm run test:ui`: Chromium 390×844 и 1440×1000; 11 основных страниц, старые адреса, создание четырёх дополнительных целей с отметкой шагов на каждом размере, английские настройки/аналитика/вход — успешно. В демотесте внешние запросы запрещены.
- `npm audit`: нет critical/high/moderate; остаётся одно upstream-предупреждение low для deepmerge 4.3.1 (npm показывает четыре затронутых пакета цепочки PWA). Исправленной версии deepmerge в реестре нет; предложенный npm откат PWA до 0.2.1 не применялся.
- `git diff --check`: без ошибок.

## Границы результата

Это проверенный набор изменений для следующего выпуска. Рабочая ветка `veyrarc-app`, Render и действующая база не изменялись; деплой и миграции на них не выполнялись. Размещённый staging не создан и не проверен: подготовлена защита в коде и точная процедура настройки.

Проверки GoTrue/PostgREST, доставки писем и push на отдельной размещённой Supabase ещё нужны. Локальный SQL-тест не подтверждает конфигурацию внешних сервисов. Не подтверждены защита ветки, фактический режим автодеплоя Render и настройки защиты паролей Supabase. Эти административные пункты и согласование пустого журнала миграций описаны в [PROCESS.md](PROCESS.md).

Перед будущим выпуском нужно сначала подготовить и проверить новые RPC в изолированной базе. Только после отдельного разрешения владельца применить согласованный SQL к рабочей базе, затем публиковать frontend. Публикация frontend до SQL приведёт к отказу составных операций и импорта.
