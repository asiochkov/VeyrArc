# Kickoff-prompt для Claude Code

> Скопируй ВСЁ, что ниже пунктиром, и вставь в новый чат с Claude Code (проект `veyrarc`, при подключённой папке репозитория). Он сам прочитает спецификацию и выдаст план подтверждения.

--------------------------------------------------------------------------------

Я положил в `docs/VEYRARC-MOTION-SPEC.md` полное ТЗ по motion-дизайну для VeyrArc. Твоя задача — прочитать его целиком, а потом реализовать по фазам в 6 отдельных PR (по одному на фазу). Мы работаем строго по спеке — ничего не «улучшаем» без спроса, ничего не пропускаем.

**Твои шаги (по одному, ждать моего «go» между фазами):**

1. Прочитай `docs/VEYRARC-MOTION-SPEC.md` полностью, а также:
   - `app/package.json`
   - `app/src/main.tsx`
   - `app/src/styles/tokens.css`
   - `app/src/styles/global.css`
   - `app/src/app/AppShell.tsx`
   - `app/src/app/router.tsx`
   - `app/src/app/Rail.tsx`
   - `app/src/app/BottomBar.tsx`
   - `app/src/ui/primitives.tsx`
   - `app/src/pages/today/HabitRow.tsx`
   - `app/src/pages/tracker/Tracker.tsx`

2. Подтверди план в 5 пунктах: что за библиотеки, что за фазы, где границы. **Не редактируй ни одного файла.**

3. Спроси меня, с какой фазы начинаем. Обычно с Phase 1 (Foundation), но не решай за меня.

4. Когда я скажу «go phase N» — выполняй ровно секцию N из спеки, ровно в том порядке, ровно с теми именами файлов и функций. Каждая правка — в отдельном коммите с сообщением из §9 спеки.

5. Перед коммитом каждой фазы: `pnpm typecheck`. Если падает — фикси и досылай. Не коммить сломанное.

6. После коммита фазы — стоп, отчитайся: «Готово N. Diff: [короткая сводка]. Готов к N+1?». Ждёшь моего ответа.

**Что нельзя:**
- Заменять `motion` на `framer-motion` (это разные пакеты; мы едем на `motion`).
- Ставить `gsap`, `react-spring`, `@react-spring/*`, `lenis`, `three`.
- Трогать бизнес-логику (`data/*`, `lib/supabase.ts`, `useTodayState.ts` — за исключением явно указанных в спеке правок).
- Менять дизайн-токены цветов или типографики.
- Делать «улучшения» переходов, которых нет в спеке. Если хочешь предложить — пиши в чат, реши со мной, потом делай.

**Что можно:**
- Задавать вопросы, если в спеке что-то неоднозначно.
- Предлагать более изящные code-паттерны в рамках одной фазы, если они не меняют поведения.
- Использовать `git diff` и `git status` свободно.

Начинай с шага 1.
